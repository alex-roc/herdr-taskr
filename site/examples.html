Ways to work with it

Workflows to copy. Each one assumes you've done the tutorial, or at least installed taskr and made a project.

  • A bug fixed in its own worktree

  • Back after a reboot
  • Several agents, one list
  • Plan work already started

  • Capture a task from any terminal

A bug fixed in its own worktree

You're in the middle of something on main and a bug report comes in. You want an agent on it without touching your checkout.

  1. Press n. Title: Checkout total ignores the coupon. Pick the folder, due today, next step Write a failing test first, then press t to put it at the top.
  2. Press w. taskr creates task/checkout-total-ignores-the-coupon in ~/.herdr/worktrees/<repo>/… and starts your agent there, with the title and the next step as its first message.
  3. Keep working. The task sits under Working with the agent's model and time; you'll see it jump to Needs you if it asks.
  4. When it stops, it shows under Finished. Open the detail, check Changes, then Ask for a pull request: once the PR is open, the task moves to To review by itself (it has its own branch).
  5. If CI fails, Send failed checks sends the agent their names. When the PR is merged, right-click → Archive and choose Archive and remove worktree.

Issues into a week of work

GitHub or Linear has a pile of open issues and you want a plan you can actually work through.

  1. In Projects, right-click the folder → Import GitHub issues (or Import Linear issues for the ones assigned to you, most urgent first, with their due date). Tick the ones worth doing; they arrive in the Inbox with the issue's link and text attached.
  2. Open the board (cmd shift b) and drag what you'll do this week from Inbox to Next.
  3. In the list, drag the tasks of Next into the order you'll do them, and give due dates like wed or fri.
  4. Start an agent on the top one with l. It gets the issue's text in its first message, so it starts with the full report.

Issues you've already imported don't show up again in the list.

Back after a reboot

The machine restarted overnight. Three tasks had agents mid-conversation.

  1. Open Herdr and switch to taskr. The tasks are where you left them; their agents are gone.
  2. Select the first one and press r (or Resume agent in the detail). Its Claude Code or Codex conversation continues in the folder it was in, in a new tab tied to the task.
  3. Do the same for the others. Each moves back to In progress as soon as its agent starts working.

Glance at the status bar before you start a big batch: it shows how much of your Claude and Codex limits is left, and when each resets.

Several agents, one list

Three agents on three tasks, maybe in different folders. You want to spend your attention where it's needed, not cycle through tabs.

  1. Start each from its task (l or w). Each opens in its folder's space.
  2. Stay in Now. Whatever is blocked is on top with its question; finished work is next; working agents after that.
  3. Answer from the detail's Message the agent box, or enter to jump to the agent.
  4. Herdr's next and previous agent keys follow taskr's order, so they visit the agents in the order the list shows them.

Set a In-progress limit in the settings (the gear in the status bar) to keep yourself honest: the status bar warns when you have more in progress than that.

Plan work already started

You opened a terminal and started an agent before thinking of it as a task. Now it's grown.

  1. Find it in the list: it's a task already, with no plan, named after what the agent calls its work. It's under its folder in Projects, and in Now: in progress, or above if its agent is working, finished or needs you.
  2. Open its detail and press Plan it…: give it a real title, a project, a next step and a due date. Or press e. From now on it's yours, and it stays until you mark it done.
  3. Started a second agent for the same job? Right-click the first task → Move to task… and pick the other: its agent, conversations and time go there, and the first task goes. A plain terminal (shell) has Add to task… instead.

Agents that file their own tasks

An agent finishes a job and notices three more things worth doing. You'd like those in your Inbox, not lost in its scrollback.

Tasks live in one JSON file that taskr reloads within a second of any change. Add this to your agent's instructions (AGENTS.md, CLAUDE.md, or the prompt):

When you find follow-up work outside your task, add it to my task list as an
Inbox task instead of doing it: append to the "tasks" array of
~/.config/herdr-app/data/taskr/tasks.json an object with "id" (agent-<timestamp>),
"title", "folder" (~/path), "status": "inbox", "notes" (why), "priority": "high"
only when it can't wait (it goes first; otherwise last),
"created" and "updated" (ms since epoch) and "history": [{"s": "inbox", "at": <ms>}].
Keep every other field as it is, write to a temp file and rename it over the
original. Never mark my tasks done and never delete them.

The full rules, with Node and shell examples, are in docs/agents.md. taskr checks every field it reads, so a slightly wrong entry still shows up, and it never writes over a file it can't parse.

Capture a task from any terminal

An idea comes up while you're in a shell. You want it in the Inbox in one line.

Add this function to your ~/.zshrc or ~/.bashrc (it needs jq):

todo() {
  local f=~/.config/herdr-app/data/taskr/tasks.json now=$(($(date +%s) * 1000))
  local folder=$(git rev-parse --show-toplevel 2>/dev/null | sed "s|^$HOME|~|")
  [ -f "$f" ] || echo '{"tasks":[]}' > "$f"
  jq --arg t "$*" --arg r "$folder" --arg id "cli-$now-$RANDOM" --argjson n "$now" \
    '.tasks += [{id: $id, title: $t, folder: (if $r == "" then null else $r end),
      status: "inbox", created: $n, updated: $n, history: [{s: "inbox", at: $n}]}]' \
    "$f" > "$f.tmp" && mv "$f.tmp" "$f"
}

Run inside a git repository, the task is tied to its folder, so it shows under that folder in Projects.

Drive taskr from scripts

You want a shortcut, a launcher or another tool to open taskr's views.

taskr answers these commands while its layout is on screen:

herdr-app do taskr.new             # the New task form
herdr-app do taskr.jump            # find a task
herdr-app do taskr.board           # open (or go to) the board
herdr-app do taskr.view            # switch Now and Projects
herdr-app do taskr.settings        # the settings
herdr-app do taskr.select:<id>     # show that task's detail
herdr-app do layout.toggle '{"id":"taskr-detail"}'  # show or hide the detail

For example, a Raycast or Alfred command that runs herdr-app do taskr.new gives you a global "new task" key.

A weekly review

Friday afternoon. What moved, what's stuck, what's next.

  1. Under In progress, a task that hasn't moved in a few days (you set how many) shows its time in yellow. Decide each one: back to Next, Waiting on… someone with a day to follow up, or Dropped. Later holds what you parked, and what you wait on comes back by itself.
  2. The board's Done column shows the last seven days; the status bar counts what you finished today.
  3. Finished tasks are in the board's Done column. Archive what's settled to put its tabs away.
  4. Drag next week's work from Inbox onto Next, in the order you'll do it.
